## Research Boundary

GDN-next work starts from this freeze and may change the learned memory write
target. It must not:

- add Sudoku rules, repair, search, selectors, or oracle inference;
- rename reverse scanning as FutureSeed;
- silently replace official FLA kernels or fall back to Torch/CPU;
- claim a stronger baseline from a short-budget opening result;
- run hyperparameter tables instead of a decision-changing mechanism test.

The first proposed mechanism is a successor-state writer: a causal student
predicts a future contextual target and writes that prediction through the
existing GDN2 recurrence. It will be accepted only if it improves hard-board
closure or loop correction under a matched budget, not merely because an
auxiliary prediction loss decreases.
